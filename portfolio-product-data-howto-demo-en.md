# Product Data Sheet: A Beginner-Friendly Preparation Guide

> Synthetic demonstration for a portfolio. It is not client work. The example uses field descriptions rather than invented product specifications.

## Goal

Prepare a clean, reviewable product-data sheet before writing e-commerce descriptions. The sheet should make it easy to see which facts are confirmed, which are missing, and where each value came from.

## 1. Start with one source of truth

Collect the source files the seller has approved: product export, SKU list, price file, stock report, product photos, and brand guidelines. Do not copy values from an old listing when a newer source file exists.

Create a working copy. Keep the original files unchanged so every value can be checked later.

## 2. Use consistent columns

A practical starter sheet can contain:

| Field | What to enter | Quality check |
|---|---|---|
| SKU | Exact seller SKU | Preserve letters, hyphens, and leading zeros |
| Product title | Current approved name | Keep spelling and variant consistent |
| Variant | Size, colour, model, or pack size | Do not merge different variants |
| Price | Amount and currency | Record the source and date |
| Stock | Current quantity or status | Do not estimate missing stock |
| Image URL | Link to the supplied image | Open the link and check the item matches |
| Key facts | Material, dimensions, compatibility, contents | Copy only supplied or verified facts |
| Source | File name, sheet, row, or URL | Make the value traceable |
| Status | Verified, needs review, or missing | Never treat blank as zero |

## 3. Preserve exact identifiers

Treat SKUs, model numbers, and variant codes as text. Spreadsheet software can otherwise remove leading zeros or reformat long identifiers. Do not “correct” an identifier unless the source owner confirms the change.

## 4. Separate facts from marketing language

A product description can explain benefits, but it must not invent specifications. If the source does not state a material, warranty, certification, size, or compatibility claim, mark it as missing and ask the seller.

For example, write “Material: not provided” in the review sheet rather than guessing “stainless steel” from a product photo.

## 5. Draft the listing only after the data check

A simple description structure is:

1. One-sentence summary of what the product is.
2. Two or three benefits directly supported by supplied facts.
3. Important specifications and variant details.
4. What is included in the package, if confirmed.
5. A clear next step, without unsupported guarantees.

Use the client's target keywords naturally. Do not repeat keywords unnaturally or add claims solely to improve search ranking.

## 6. Run a final quality check

- [ ] Every SKU matches the source file.
- [ ] Price and currency are present and current.
- [ ] Stock values are not guessed.
- [ ] Each image link opens and matches the correct variant.
- [ ] Product claims are supported by the supplied facts.
- [ ] Missing information is flagged for review.
- [ ] Titles and descriptions follow the brand guide.
- [ ] The change log identifies what was edited.

## Delivery format

Provide the completed spreadsheet, a separate document containing the approved descriptions, and a short change log listing unresolved questions. Ask the client to review the data sheet before publishing the listings.
